# 医枢 MedNexus

根据本次提供的两份 Word 文档、区别说明、项目记录和三张界面图片实现的本地医学主动学习智能体原型。它围绕一个知识点推进学习：进入章节后主动诊断，按要点判断缺口，提供定向补学，遇到具体开放性疑问再连接 PubMed，最后用迁移题返回同一个知识点。

## 与原「书页」项目的合并说明

2026-10-24 完成了两套原型的合并：**保留本项目的教学流程，替换它的证据层**。

| 部分 | 来源 | 说明 |
|---|---|---|
| 诊断 → 三要点评分 → EMA 掌握度 → 补学 → 迁移 → 报告 | 本项目 | 未改动 |
| 教材页级检索（`textbook.py`） | 书页 | **新增**：BM25 + IDF 覆盖率，命中即返回印刷页码 |
| 拒答门槛（覆盖率 + 至少命中 2 个词） | 书页 | **新增**，取代原先只看自编学习卡的策略 |
| PubMed 检索 / 证据分级 / 缓存 | 本项目 | 未改动 |
| 学研判断闸门 `research_gate` | 本项目 | 未改动 |

行为变化（会影响旧测试与旧文档表述）：

1. 自由提问**优先返回教材原文段落**（`kind: textbook`，带 `page`），索引未命中才回退到自编学习卡（`kind: note`，`page` 为 `null`）。
2. 因此原先“所有引用都不带页码”的断言已更新为“只有教材索引来源可带页码，学习卡不得带页码”。
3. 索引文件放在仓库根目录 `chunks.jsonl` 或 `mednexus/data/chunks.jsonl`，**不入库**；没有索引时系统仍可运行，只是没有页码可引。

## 启动

需要 Python 3.10 或更新版本，无需安装第三方 Python 包或 Node.js。

双击本目录的 `启动医枢.bat`，浏览器会打开 `http://127.0.0.1:7860`。保持启动窗口运行，按 Ctrl+C 停止服务。也可以从终端执行：

```powershell
cd mednexus
python server.py --open
```

移到其他电脑后，先安装 Python，再双击启动脚本。脚本按自身位置寻找文件，不依赖原电脑的中文绝对路径。端口占用时可运行 `python server.py 7861 --open`。请通过服务地址访问，不要直接双击 `web/index.html`。

## 课程包：课程内容不在代码里

课程数据在 `data/courses/anatomy.json`，顶层字段为 `course` / `chapters` / `sources` / `concepts` / `questions` / `hints` / `query`。`course_loader.py` 在启动时校验，`knowledge.py` 只是加载层，改一道题不需要动 Python。

校验内容：题号与知识点 id 唯一、每个知识点同时有诊断题和迁移题、每道题恰好三个要点且选项互不重复且包含正确答案、`course.goal_source` 必须写明、`syllabus_refs` 必须是字符串数组。

**加载分两种模式**：

| 模式 | 谁在用 | 遇到问题会怎样 |
|---|---|---|
| 非严格（默认启动） | `python server.py` | 坏掉的知识点或题目**单独丢弃**，原因打印成 `[course-package] 错误：…`，其余内容照常服务，页面仍能打开 |
| 严格 | `python course_loader.py` | 汇总全部问题后抛错并返回非零，适合提交前自查 |

所以改坏一道题不会让整个网页打不开；但控制台会出现 `[course-package]` 开头的行，不要忽略它。

换一门课或做多个课程包，不用改代码：

```powershell
set MEDNEXUS_COURSE_PACKAGE=D:\path\to\another-course.json
python server.py --open
```

### 大纲映射（`syllabus_refs`）

`syllabus_refs` 只写大纲条目 id（如 `syllabus-290`），**不复制原文**。本机存在 `data/course_materials/syllabus.json` 时，前端才会把它解析成“章节·要求原文”显示在知识点面板；没有这份私有资料时该行不显示。空映射和查不到的条目只会告警、不阻断加载，**不会替人猜测填充**。新增映射的做法是照着本机大纲里的 id 填进去，再跑一次 `python course_loader.py` 看有没有提示。

## 已实现的使用流程

1. 总览展示真实的学习记录，推荐最需要巩固或尚未测评的知识点。初始数据全为零，不使用设计图里的虚构成绩。
2. “我的学习”提供脑神经示例章节、分组知识点、推荐任务和四种学习入口。自动评分仍覆盖 10 个知识点、20 道三要点题；完整大纲可以另在“课程资料与题库”查阅。
3. 首页点「开始学习」进入课程与章节，选择推荐任务或知识点后直接出题；答错时显示缺失要点并提供补学，答对时进入迁移题。
4. 每道题包含三个独立要点，分别选择、分别计分。全错先补基础，部分正确补缺失环节，诊断题达标后做迁移题。
5. 补学内容显示本次缺失的要点和对应解释；阅读只算覆盖，不改变掌握度。
6. 首页自由提问只在索引含书名、章节、页码和可核对短段落时给教材要点；缺少教材时明确拒答。教学引擎仍可单独检索自编学习卡，不把学习卡标成教材页码。
7. 学习评估的结果页可提交具体疑问给研究判断闸门；记忆性疑问引回基础学习，符合条件的开放性问题再由用户主动进入文献漫游。英文检索式来自人工模板，不能保证逐句翻译。
8. PubMed 官方 E-utilities 实时检索，显示实际返回的标题、作者、期刊、年份、PMID、摘要、类型和链接。不预装或补造论文列表。
9. 阅读卡保留原疑问，按真实摘要标签展示研究问题、方法、结果、结论、局限及未分栏节选，并链接原始PMID。独立主题也可打开阅读卡；从知识点进入时可返回原知识点做迁移题。
10. 学习评估页展示实际要点评分、错误类别、首次与最近作答及可解释的掌握判断。个人中心支持下载学习摘要，以及分别清理学习记录或同时清理当前身份导入的索引。

### 主动学习计划与分步提示（2026-10-29）

首页“今天从这里开始”和右侧计划来自同一份真实记录：优先继续未完成题目，其次复习薄弱要点和到期任务，再推荐新知识。每天最多推荐2个新知识点，一次显示最多5项；“今日已练”统计上海时区内作答过的不同知识点。“到期待练”包含立即需复核的薄弱点与迁移任务，统计范围为整个脑神经示例章节。

诊断与迁移都有独立达标记录后，复习间隔由 `srs.py` 的 FSRS-lite 模型计算：每个知识点维护稳定度、难度与上次有效复习时间，遗忘曲线取 `R(t) = (1 + t/9S)^-1`，间隔由目标保持率（默认 90%）反解。连续独立迁移达标会让稳定度按 `1 + (15 − 1.2D)(1 − R)` 增长（上限 3 倍），答错把稳定度压到 1 天以内并抬高难度。同一天重复高分不会推迟到期时间；提示辅助、教学对话、自由文本判分都不推进稳定度，低分后重新巩固。状态由作答历史重放得到，不写数据库。该模型是可解释的工程近似，尚未用真实复习数据拟合或验证，也没有新增外部提醒或后台自动通知。

每个评分要点可主动展开两步思路提示：先分析题干条件，再整理结构、功能与表现之间的推理。当前提示是预设思考框架，不是开放式多轮导师。离开页面或刷新后可恢复同一任务与已用提示；只要使用过提示，本次整题标为“辅助练习”，不能用于建立独立掌握证据。结果、报告和学习记录导出会保留该标记。服务端记录提示使用情况，不能通过浏览器提交字段改成独立作答。

计划与提示均在本机运行，无模型API费用。课程大纲、OCR翻卡与书页问答尚未自动转换为已审定评分题，因此不混入该复习计划。

### 作答草稿、信心与推理（2026-10-31）

未提交的三个要点选择、可选信心和推理记录仅保存在当前窗口的sessionStorage，按学习身份与任务令牌匹配。刷新恢复同一道题的原选项，不自动提交、计分或调用模型；换题不继承旧题草稿。提交成功或清理学习记录后删除对应草稿，提交失败保留供重试。浏览器禁止存储时提示可能无法恢复，当前作答仍可继续。

信心默认“暂不记录”，可选不确定、一般或很有把握；高信心但要点评分未达标时提示回看依据，不改变原分数或掌握规则。新记录区分学生自报与未填写；旧记录中的信心可能由旧页面默认填写，结果页不将其显示为学生自报，导出以 `legacy_default` 标识该来源。

可选推理最多3000字，提交后保存在本机学习记录中，最近结果展开可回看，刷新后仍可恢复；不参与自动评分、不自动发给教学模型、不包含在学习摘要导出中。明显联系方式、身份和病历字段在草稿及提交前拒绝保存；这不是完整去标识化工具，请勿输入个人或患者资料。提交期间锁定选项及补充输入，避免实际显示与提交内容不一致。

### 在页面中校对与整理

在“课程资料与题库”选择“组胚原图与知识检索”，可按尚未核对、优先核对、本机修订筛选文字。展开某行“编辑 / 核对”会定位原图，修改后可保存；只有主动勾选“已对照原图核对本行文字”才标记为本机已核对，继续改字会取消该勾选。修订立即用于本机资料检索，刷新后保留。

修订写入本机 `data/course_materials/histology.reviews.json`，保留每次保存及恢复记录；“恢复识别底稿”保留历史，不覆盖导入的原OCR。不同窗口修改同一行时，后保存者必须重新载入，不会静默覆盖；跨服务进程也会串行保存，避免覆盖整份历史。重新运行OCR导致原行变化时，也必须重新核对。页面中的独立表格整理稿保留首次转录，不随逐行修订自动改写。

未保存的逐行草稿保留在当前窗口内存中，切换筛选、翻页或保存其他行后仍可继续编辑；刷新或关闭前会提醒保存。遇到其他窗口修改，重新载入后保留草稿，并显示当前已保存文字供比较，需明确选择基于当前版本继续草稿。草稿尚未写入本机修订文件，关闭窗口后不能作为已保存资料找回。窄屏打开编辑器只定位图片内框，避免整页滚离输入框。

原图支持适应宽度及150%／200%／300%缩放，条目可按当前筛选结果的序号跳转。“导出当前筛选文字”下载当前匹配的全部条目，保留来源定位和待校对说明，不因文字片段筛选而丢失上下文。资料页面在桌面使用完整主区宽度。

这些校对记录属于本机共享的课程资料；个人中心清理匿名学习记录不会删除它们。核对标记只代表使用者对图检查，不等于教师审定，也不进入正式测评得分。

## 研究焦点与英文检索建议（2026-11-01）

从知识点进入文献漫游，先核对原疑问，再展示可编辑英文式与词语对照。对单一、明确的恢复、预后、病因、机制或结局评价指标，规则保留当前知识点的核心英文主题，并建议对应的Title/Abstract条件；原预编研究疑问仍使用其配套模板。页面可比较、恢复原模板，或使用焦点建议式，这些操作只修改草稿，点击查询才发出检索。

这只是有限词语匹配，不是逐句翻译或科研价值判断。包含多个焦点、话题否定、犹豫或跨神经/肌肉比较时，保留原模板并说明原因；人群、比较对象、时间等条件需人工核对。用户手动编辑的实际英文式优先，接口仍检查主题核心词、类型、长度和明显个人信息。刷新保留编辑草稿；词语对照不保存，若需重新建议可再次判断原疑问。检索语法参考[PubMed官方帮助](https://pubmed.ncbi.nlm.nih.gov/help/)。

## 文献阅读卡（2026-11-01）

从课程知识点进入或独立搜索医学主题后，都能点击“阅读摘要与证据”。阅读卡依据PubMed XML的NlmCategory及明确的原摘要标签分栏，保留标签与原文节选。没有可识别标签的段落单列为未分栏摘要，不自动猜测其研究设计或结论；未识别的环节收在核对提示中，不等于论文没有报告。

每段最多300字、整张卡最多1500字、最多12段，并提示段落截断和省略情况。原文节选不是中文翻译或全文解读，也不等于研究质量评价。无摘要时引导核对PubMed原始记录；查询修改或新疑问会使旧阅读内容失效，读取失败可重试同篇摘要。独立主题不会被自动绑定脑神经知识点或制造迁移题。

分类依据：[NLM AbstractText XML规范](https://dtd.nlm.nih.gov/ncbi/pubmed/doc/out/250101/el-AbstractText.html)。原始标签的存在不证明研究质量，未结构化摘要中的结果仍需使用者打开原文人工核对。阅读操作不计分、不增加掌握记录；本轮未新增付费模型依赖。

## 开放获取全文、证据字段与引文导出（2026-11-08）

阅读卡新增一层可选的开放获取全文。点“加载开放获取全文”后，服务端按 PMID 做 PMC 编号转换，再取 JATS XML，只保留方法、结果、讨论三类段落，按全文顺序编号，每段带 `[PMID:段落号]`。段落编号只表示位置，不表示重要性；正文原样截取，不翻译、不改写、不生成结论。

**许可闸门**：只有 CC0、CC BY、CC BY-SA、CC BY-NC、CC BY-NC-SA 这类允许摘录与再分发的许可才展示正文。ND 变体、All rights reserved 或许可不明时，**一个字都不返回**，只说明许可与原因并降级为摘要。全文与许可决定缓存在本地 `fulltext` 表，成功的缓存 7 天、被拒绝的缓存 1 天，避免反复请求 NCBI。

**四种降级**：没有 PMCID、PMC 没有正文、许可不允许、网络失败，都会返回明确原因并只展示摘要；界面不会把摘要讲成“已读全文”。

**证据字段提示**（不是质量评级）：只从 PubMed 文献类型与摘要原文抽取研究类型、样本量、随机化、盲法四项。摘要没写就显示“摘要未报告”，不推断；给的是核对提示（例如“未提到盲法时主观结局的效应估计可能偏高”），并明确写“不能凭文献类型判定质量”。

**引文导出**：`/api/export-citations` 按检索缓存输出 BibTeX 或 RIS。缺卷期页码就不写，不补造；不在缓存里的 PMID 直接拒绝。界面提供“复制 BibTeX / 复制 RIS”。

## 代码结构与请求观测（2026-11-08）

`server.py` 原来是一个约 1500 行的单文件，现在按域拆到 `mednexus/api/`，HTTP 契约与 `/api/*` 路径**完全不变**：

```text
mednexus/
  server.py            入口与兼容层：`python server.py` 照旧可用，旧名字照旧可导入
  api/routing.py       路由、request_id、耗时日志、SSE 流式辅导
  api/core.py          共享底座：路径、锁、SQLite 连接、学习状态读写
  api/task.py          出题、恢复、提示、多轮辅导
  api/answer.py        三要点选择题判分、自由文本判分
  api/study.py         资料来源、检索、补学、导入、组胚识图
  api/ask.py           自由提问与教材依据
  api/research.py      PubMed、PMC 全文、证据字段、引文导出
  api/report.py        快照、学习报告、导出、首页总览
```

拆分只搬代码、不改逻辑：函数体原样迁移，335 项既有测试**一行未改**全部通过，这是“契约没变”的证据。`server.py` 保留了兼容层——`server.DB_PATH = ...`、`server.pubmed = ...` 这类既有写法仍会作用到真正被调用的实现，所以老测试夹具不需要改。

**请求日志**：每个请求生成 12 位 `request_id`，响应头带 `X-Request-Id`，stderr 打一行

```text
[http] POST /api/tutor -> 200 42.3ms rid=6b546849d44c
```

只记方法、路径、状态码、耗时和 rid。查询串、请求体、学习内容、令牌一律不记（`test_routing` 有断言）。

**SSE 流式辅导**：`POST /api/tutor/stream` 返回 `text/event-stream`，事件顺序为 `meta` → 若干 `chunk` → `done`。原来的 `POST /api/tutor` 不变，前端不支持流式时自动回退。

```text
event: meta
data: {"request_id":"…","mode":"本地资料对话","warning":""}

event: chunk
data: {"text":"瞳孔不一定散大，因为…"}

event: done
data: {"messages":[…],"remaining":11}
```

**注意**：模型输出先经过引用校验，再分段下发——不是把未校验的模型 token 直接透传给页面。前端在收到 `done` 之前只显示正文，来源与模式在完成后再渲染。

## 内容和能力边界

这是可运行、可扩展的原型，不是经过医学教师审核的正式教学平台。

- 已提供的课程大纲保留在本机，尚未提供带可核对页码的教材正文或正式国家考纲。旧项目说明中的命中率与用户测试成绩不移植为本版本成绩。
- “掌握／熟悉／了解”是示例教学目标。界面明确注明待医学教师审核，没有把自编层级称为官方标准。

- 离线诊断采用结构化选择，补充自由文本推理只保存供人工复核，不冒称已实现可靠的开放式语义评分。

- 不含导师匹配、模拟病人、账号登录或互联网多人部署。本地匿名学习身份用于区分记录，不是经过加固的多用户认证系统。

## 评分与决策

每道题三个要点等权，答对 0／1／2／3 个分别约为 0／33／67／100 分。首次掌握度取首次原始得分，此后：

```text
EMA = 0.4 × 旧掌握度 + 0.6 × 本次原始得分
```

标记“已掌握”同时要求：两个不同题目的最新作答均为独立作答且至少 80%，包含迁移题；最近两次均为独立作答且至少 80%；EMA 至少 80%。辅助练习仍记录原始得分和EMA，但不能满足独立达标条件。因此重复同一道题、只读学习卡、提示后的满分或单次满分都不足以标记掌握。之后出现错误或辅助作答可能降低当前状态。此判断为可解释的工程规则，尚未验证为有效的认知测量模型。

“首次／最近”可能是不同难度、不同情境的题目，仅是过程记录，不是教学效果实验或因果证据。报告不会将自测过程包装为真实用户试验。

## 组胚识图练习（2026-11-08）

55 张组胚原图现在可以出识图题。标注由脚本从本机 OCR 抽取，生成 `data/course_materials/histology_labels.json`（**不入库**，随资料一起留在本机）：

```powershell
python tools/build_histology_labels.py
```

每页记四类字段：`tissue`（组织，按关键词表计数）、`stains`（染色法）、`structures`（原文自己编号的小标题）、`source_page`（来源页）。全部带 `review_status: pending`。

**题目形式**：给出一页图，问它的小标题是下面哪一项（4 选 1）。正确答案就是 OCR 从那张图上抽到的小标题，可以人工核对。

> 为什么不是"在图上点出结构"：这 55 张图是**复习笔记扫描页**，OCR 框是文字行的框，不是切片里的解剖结构位置。凭空画结构框等于编造医学标注，所以本版只做能核实的事。如果以后换成真实切片照片并给出结构坐标，接口层已经支持按坐标判分的扩展点。

**与文本题隔离**：答题写入同一条 `attempts` 记录，但 `kind='image'`、`concept='histology'`。`progress()` 只遍历课程知识点，所以图片题不进 EMA、不进掌握度；学习报告与导出也会跳过它们。`/api/overview` 里的 `image_quiz` 是独立的计数与正确率。

**视觉模型（可选，默认关闭）**：设置 `MEDNEXUS_VISION_MODEL`（本机 Ollama 已安装的视觉模型名）后，界面多一个"让本机视觉模型描述这页（仅辅助）"按钮。描述一律标"未核验，不能作为答案依据"，不参与判分、不进选项。没配置时就是纯标签检索。

界面在"课程资料与题库"页顶部，横幅写明**标注待教师审核**。

文献疑问、原知识点和已编辑检索式仅存于当前窗口的sessionStorage，按匿名学习身份隔离；刷新恢复草稿，不自动查询或保存论文结果。清空草稿或清理学习记录会移除它，浏览器禁止存储时仍可在当前页面检索。明显个人信息不会写入草稿；检索前仍须自行避免输入个人或患者资料。
