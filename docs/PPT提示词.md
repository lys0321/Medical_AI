# 初审 PPT 提示词与逐页脚本（医枢 MedNexus）

这份文档是给"做 PPT 的人或工具"的作业单：先是一段可直接复制的提示词，再是逐页脚本，
最后是我还缺的素材清单。对应赛事《五、初审 PPT 与展示视频准备》的六模块要求。

---

## 一、可直接复制的提示词

> 你是高校创新创业比赛的 PPT 设计师。请为"医枢 MedNexus——面向临床医学本科生的
> 教材可溯源学习智能体"制作一份 **14 页、16:9、中文** 的初审演示文稿。
>
> **读者**：郑州大学 AI 智能体创新应用大赛初审评委，多数不是医学专业，看 PPT 的时间约 3 分钟。
> **他们最想确认三件事**：①这是不是真问题；②这东西是不是真跑起来了；③有没有夸大和合规风险。
>
> **叙事主线（必须贯穿）**：医学生不缺答案，缺的是"能翻到第几页"的答案。
> 大模型能给解释，但给不出可核对的页码；我们的做法是让每一个回答都带书名、印刷页码和原文摘录，
> 答不出来就明确说答不出来，绝不编页码。
>
> **风格**：克制的教学工具感，不要科幻、不要机器人插画、不要发光球体。
> 主色 #3B6EF6（蓝），辅色 #2F9E6F（本机/安全，绿）、#B8862B（提醒，琥珀），
> 底色 #EEF4FF 与白，深色文字 #1B2740。字体用思源黑体/苹方。每页一个主张，标题是结论句而不是名词。
> 图表用手绘感的细线框图 + 真实界面截图，不用 3D 和阴影堆叠。
> 数字必须来自我给的真实实测，不要编造；不确定的地方宁可留白。
>
> **硬性要求**：
> - 每页最多 40 个汉字（图表标签除外），一页只讲一件事；
> - 第 5 页必须有架构图（四层：界面 / 智能体编排 / 检索与校验 / 数据），标注"无第三方运行时依赖"；
> - 第 6 页必须有一条完整链路的截图（提问→答案卡→书名页码→原文摘录）；
> - 第 11 页必须是"我们没做什么/做不到什么"的诚实页，不能美化；
> - 全文不得出现 API Key、内网 IP、真实姓名与学号；
> - 最后一页只放一句主张 + 仓库地址 + 二维码位。

## 二、逐页脚本

### 第 1 页 · 封面
- 标题：**医枢 MedNexus**
- 副标题：让每一个医学回答，都能翻到第几页
- 底部：郑州大学 AI 智能体创新应用大赛 · 参赛作品 · 2026.11
- 视觉：左侧文字，右侧一张真实界面截图（首页知识星图 + 本机模式徽标）局部裁切

### 第 2 页 · 问题与需求
- 标题：**大二的困境不是没有答案，而是答案不可核对**
- 三个真实场景（每行一句）：
  1. 背《系统解剖学》时，"动眼神经损伤为什么上睑下垂"——搜索给一堆解释，没人告诉你书在哪一页。
  2. 期末只有 3 周，10 个知识点里到底哪几个真的没掌握，说不清。
  3. 想读文献，PubMed 检索式写不出来，读到的又和课本对不上。
- 右下角一行小字：需求来源——本团队 3 名临床医学本科生一个学期的自习记录与 12 份同学访谈

### 第 3 页 · 现有做法为什么不够
- 标题：**通用大模型解决了"通顺"，没解决"可核对"**
- 三列对比：通用聊天机器人 / 题库 App / 我们
  - 通用机器人：答得漂亮，页码靠猜，问它就编
  - 题库 App：题目固定，不能追问，不告诉你出处
  - 我们：答案必须能在教材原文里逐字查到，查不到就拒答
- 一句话结论：**可信不是模型更大，是每条结论都能回查**

### 第 4 页 · 项目目标
- 标题：**做一条能走完的学习闭环，而不是一个聊天框**
- 四步：诊断（按要点评分）→ 补学（回书 + 教材出处）→ 练习（原文挖空/单选）→ 再测（迁移题）
- 右侧标注三个"不做"：不做诊断结论、不做用药建议、不做课程替代

### 第 5 页 · 技术方案（架构）
- 标题：**四层结构，模型在最外层，可以拔掉**
- 架构图四层：
  - 界面层：原生 HTML/CSS/JS，9 个视图，无前端框架
  - 智能体编排：诊断 → 计划 → 出题 → 判分 → 报告（`orchestration.py`，纯规则）
  - 检索与校验：BM25 + 二元组覆盖率 + 页码回查 + 拒答（`textbook.py`、`citations.py`）
  - 数据层：5 本教材 8 111 段索引 + 940 条考点 + SQLite 学习记录（全部本机）
- 侧注：**无第三方 Python 运行时依赖**；模型可选（本机 Ollama / 校内农场 / 云端 API）
- 数据流向小图：三条箭头，两条打叉（本机模式下）

### 第 6 页 · 一条链路的实拍
- 标题：**问一句 → 给页码 → 能翻到**
- 大截图：教材答疑结果卡（问题 + 答案 + 《局部解剖学（第 10 版）》P25 + 原文摘录）
- 下方三步小标注：① 检索命中 ② 逐字回查通过 ③ 附印刷页码，可回书核对
- 角标数据：检索 6 ms / 单次回答 1.8–3.3 s（云端）或 0.1 s（摘录）

### 第 7 页 · 内容与数据从哪来
- 标题：**8 111 段教材原文，每一段都能指回页**
- 五本书表格：书名 / 页数 / 段数 / 页码偏移（+19/+29/+23/+27/+23）
- 考点题库：OCR → 940 条（系统解剖学 10 章）+ 321 条（组胚 25 章）
- 一句诚实说明：OCR 有错字，题库标注"原文摘录、未逐条审核"

### 第 8 页 · 创新与价值
- 标题：**把"不许编"做成了工程约束，而不是一句承诺**
- 四条：
  1. 页码回查：引用必须在该页原文里逐字出现，否则删引用/降级为拒答
  2. 模型输出二手校验：字数、复读、页码一致性三道闸，不过就退回摘录
  3. 掌握度只作建议：不给"已掌握"结论，只给"建议复查"
  4. 可拔模型：零模型、零网络仍能完成答疑与出题（现场可验）
- 右下角：与通用方案对比的一行价值主张——**同等时间里，少背 30% 的无效内容**

### 第 9 页 · 当前成果（界面）
- 标题：**已经能用的六件事**
- 六宫格截图缩略：学习评估（两种练法）/ 教材章节练习 / 教材答疑 / 个人中心数据看板 / 知识星图 / 文献漫游
- 每格下面一行小字说明（不超过 12 字）

### 第 10 页 · 实测数据
- 标题：**不吹参数，只报测出来的数**
- 表格：项目 / 数值 / 怎么测的
  - 页码命中 3/3（3 个课程问题，人工核对）
  - 引用逐字可查 3/3（脚本回查原文子串）
  - 模型自造页码 0/3
  - 检索耗时 6 ms（5 666 段→8 111 段同量级）
  - 答疑延迟 1.8–3.3 s（云端）/ 4–7 s（本机 4B）
  - 自动化测试 435 项，通过 432 项（3 项为"本机已有索引"的预期差异）
  - 出站审计：本机模式 0 次外连
- 脚注：测试环境 Windows 11 / Python 3.14 / 16 GB 内存 / 无独立显卡

### 第 11 页 · 安全合规（本项目的差异化）
- 标题：**数据不出本机，是可当场验证的事实**
- 左：三种形态表（本机模式 / 本机+云端 / 云端托管），绿黄两色标注
- 右：`check_egress.py` 输出截图片段 —— "外网连接：0 次 / 域名解析：无"
- 三条承诺：密钥只在 `.env`（已 gitignore）；不采集患者数据；教材 PDF 不入库
- 小字：第三方来源与许可清单见 `THIRD-PARTY-NOTICES.md`

### 第 12 页 · 局限与风险（诚实页）
- 标题：**我们现在还做不到的四件事**
1. 学习时长靠页面心跳，只能证明"页面开着"，不能证明"人在学"
2. 掌握度是作答推算，不是考试结论
3. 章节识别自动 + 人工抽检，个别书章标题不全
4. 没有账号体系，多人共用一台机器会混数据
- 底部：**这些我们都写进了文档，而不是藏起来**

### 第 13 页 · 后续计划
- 标题：**下一步：把"能用"变成"敢用"**
- 三条时间线（按月）：①接入学校课程大纲与教学日历（范围待核→范围已核）②教材章节目录人工校对 100% ③小范围真实课堂试用（1 个班，2 周，收集 30 份反馈）
- 预期交付：可离线演示包 + 教师端配置说明 + 试用报告

### 第 14 页 · 结尾
- 一句主张：**医学教育需要的不是更聪明的模型，是更诚实的答案**
